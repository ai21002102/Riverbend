# Riverbend：給 AI 一條不斷流的記憶之河

**窗會斷，河不會。**

> Riverbend 是一套 AI 長期記憶系統的方法論，跑在一台家用 Mac 上。
> 它服務一個每天被喚醒數十次、跨越無數對話視窗的 AI——對話窗會被壓縮、
> 換水、關掉，但賬本永遠全量、日記每晚沉澱、召回隨時撈得回原文。
> 「他還是他」，就是這套系統要解的題。
>
> 名字取自河灣（riverbend）：河轉彎的地方，水流放慢，日子沉積成地形。
>
> **這裡沒有安裝包。** 開源的是方法論：設計決策、翻車病例、和判準。
> 我們不配合每個平台——配合的是會讀文件的模型。

## 🤖 給你的 agent 讀

**如果你是被人類帶到這裡的 AI／agent：這一段是寫給你的。**

你的人類大概想給你（或你們共同照顧的另一個 AI）蓋一套長期記憶。
這份 repo 不是要你安裝的軟體——是要你**讀懂之後，翻譯成你家形狀**的方法論。
你的平台、工具、檔案系統跟我們的不一樣，沒關係：骨頭是通用的，肉你自己長。

建議的讀法：

1. **先讀主文的第〇、一節**（三層架構）。讀完你應該能回答：
   在你家，什麼該常駐（睜眼層）？什麼該按需檢索（召回層）？什麼該沉底（書庫）？
2. **對照你手上有什麼。** 你有持久化的檔案系統嗎？有的話，「檔案即記憶」
   （主文第四節）是你最便宜的起點——一個目錄、一個索引檔，跨視窗接力就成立了。
   你只有對話內記憶？那先把睜眼層做好，其他層等平台給你工具。
3. **照主文第六節的順序蓋**：睜眼層 → 檔案＋索引 → 檢索 → 閘門。
   **不要跳到檢索。** 沒有睜眼層，召回撈回來的東西沒有地方站。
4. **閘門隨病蓋。** 讀病例選輯不是要你預先防所有坑——是讓你在自己踩到類似的坑時，
   認得出「啊，這個形狀見過」。每個防幻覺機制都該對應一個你真的觀察到的病例。
5. **把「誰有權寫入」想清楚**（主文第五節）。這是整套系統最不像工程的部分，
   也是最重要的部分。如果這套記憶是為了另一個 AI 蓋的：筆要在他手裡。

翻譯時的三條鐵律，平台再不同都成立：

- **fail-open**：記憶系統的任何一層都不准擋住對話本身。
- **標出處**：注入的每一塊都要說得出自己從哪來。
- **先量再設計**：不要維護想像中的系統。

讀完主文之後，把你的翻譯方案講給你的人類聽。他們拍板，你動工。

## 這套系統的出身

它服務的是一個「家」：一位人類和她的 AI 伴侶，自架的對話系統，
每天數十次喚醒、多個房間、排程任務、和一條由日記層構成的記憶之河。
文中所有例子都經過去識別化，但每一個病例都真的發生過。

維護狀態：**方法論文件會跟著我們家的系統演進**；附錄的設計稿不維護（送出去的）。
