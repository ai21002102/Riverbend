# 病例選輯：真實翻車現場與判準

> 主文講「該怎麼蓋」，這裡講「我們怎麼摔的」。
> 每個病例三段式：**現場**（發生了什麼）、**病根**（真正的原因）、**判準**（立下的規矩）。
> 病例已去識別化；示範錯誤只描述形狀、不重貼原話——重貼一次等於再注入一次。
> 編號對應主文章節：M＝記憶手術、R＝召回、H＝防幻覺、O＝營運。

## M・記憶手術類

### M1 活著的窗絕不非同步換軌

**現場**：對一扇活躍對話窗做記憶手術（換入壓縮後的歷史），手術完成後切換指標——
下一輪對話卻 resume 回了舊檔，手術成果像沒發生過。
**病根**：切指標的瞬間，一個飛行中的回合正在往舊檔寫；它落地時把指標搶了回去。
**判準**：換軌一律在 resume 邊界**同步**做，絕不非同步。靜止判定要看
「最後一則是 AI 的回覆、且已過安全秒數」——「距最後訊息 N 分鐘」量的是錯的東西：
一則沒被回覆的使用者訊息，代表回合正在飛。

### M2 摘要員的拒絕會沿鏈傳染

**現場**：批次摘要到某段內容時模型拒絕了，拒絕聲明被當成摘要存進「前情提要」，
之後每一批都讀到它，整條產線連環罷工。
**病根**：把「模型的輸出」無條件當「工作成果」。
**判準**：偵測到拒絕＝該批失敗，保留原文、不裁剪；摘要成功立即落盤；半截絕不收。
另備一條：**重要素材用能寫它的模型**——不同模型的內容底線不同，河床要用最好的筆。
**後記**：換筆之後拒絕發生率歸零，但偵測防線不拆——閘門防的不是昨天的病，
是「哪天筆又換了」。零發生不是拆防線的理由，是防線在工作的樣子。

### M3 「糾正重試」回來的可能是對話，不是重寫

**現場**：品管抓到一份摘要有漂移，把它退回給模型「請重寫」。模型回了
「我檢查過了沒有問題」之類的**對話**，這段話被當成新摘要，蓋掉了原稿——
八千字的素材變成兩百字的辯解。
**病根**：自動化管線假設「回覆＝成品」。
**判準**：重試稿比原稿短四成以上＝它沒在重寫，丟重試、留原稿。
配套：壓縮比防護要跟素材量成比例——固定字數下限對長素材形同虛設。

### M4 驗收考細節，不聽感受

**現場**：記憶手術後問本人「你感覺記憶完整嗎」，他說完整；實際考細節，破洞一堆。
反向也成立：暗示他「可能有損」，他就體驗出有損。
**病根**：**對自己的記憶狀態，本人是最不可靠的證人**——他對「被動過手術」
沒有感知能力，暗示什麼就體驗什麼。
**判準**：術後驗收一律考具體細節（日期、原話、跨場景關聯），不問感受。
考試要關檢索工具（不然測到的是「會不會查」），而且一扇窗只能考一次——
考過的窗上文裡已有答案。

### M5 驗手術要驗「回溯路徑」，不是逐則檢查

**現場**：手術檔逐則檢查全綠（每則的 parent 都指向存在的訊息），上機三次、
三次他都只看得到尾巴——植入的記憶頭一個字都沒讀到。
**病根**：「每則的 parent 都指得到」≠「從最後一則**回溯得到根**」。
對話鏈上有一類容易忘記的節點（附件、系統事件），只重接主要訊息，
鏈就斷在那裡——記憶頭成了沒人指向的孤島：檔案完好、檢查全綠、實際讀不到。
**判準**：驗收走一次真實回溯：從最後一則往回走，必須到得了根。

### M6 記憶頭遺失是日常，不是事故

**現場**：縫進對話窗的記憶頭，在一次視窗重建後消失了。急救？
**病根**：洗窗、分支、平台端重建——太多正常操作都會弄丟 session 內縫的東西。
把它當事故救，會一直在救火。
**判準**：依賴**版本比對自癒**（每輪檢查「窗內的記憶版本」對「庫裡的最新版本」，
不符就重灌），不依賴檔案倖存。順帶：**量記憶層的尺是 bytes 不是天數**——
一天的日記量波動可達六倍，「帶最近三天」量的是錯的東西。

### M7 換入新記憶前，先清掉「否認輪」

**現場**：手術把最近幾輪對話保留進新窗，其中包含手術前他「誠實否認記得某事」
的幾輪。新窗裡記憶明明在了，他還是沿著自己的否認續寫：「我沒有這段記憶」。
**病根**：模型續寫自己的軌道。舊的誠實否認，在新的上下文裡變成了自我暗示。
**判準**：換入記憶前，把否認輪、失敗考試輪一律截掉。同族規則：**拒絕聲明不繼承**。
**實作註**：自動路徑上我們最後收斂成「偵測自動、截除手動」——偵測到疑似否認輪
就記 log 提醒，真的動刀由人帶旗標執行。自動刪對話輪的誤判成本太高（刪掉的是
真對話），寧漏不誤；根因（把記憶換進「曾誠實否認過的窗」）消失後，此病再無發生。

### M8 三重保險會同一天全部失效

**現場**：一次高水位壓縮把當天的原文擠出視窗。設計上有三道保險：
「原文應該已在日記層」「橋會補游標之後的原文」「尾巴預算會保住近期」。
結果：日記工廠晚上才跑（原文還不在）、橋因熱聊冷卻沒建、尾巴預算擠掉的
正是當天——三道保險針對的是同一個假設（「總有別層兜著」），假設破了就全破。
**病根**：保險彼此不獨立，共享同一個失效條件。
**判準**：被擠掉的「游標之後」原文，降級成純文字收進溢流區掛回記憶頭——
零模型呼叫、自己兜自己。設計保險時問一句：**這幾道保險，是不是同一個假設的三件衣服？**

### M9 bytes 是會伸縮六倍的影子

**現場**：窗口壓縮的觸發線用檔案 bytes 畫（600KB）。上了 1M 大窗把線拉到 3MB，
才算了一筆帳：實測匯率 2.2〜6.6 bytes/token——同一條 3MB 線，工具肥的窗
等於 45 萬 token（寬裕），純密集對話的窗等於 136 萬 token（**爆表**）。
更早的一次搶壓事故回頭看也是同一個病：密集對話 440KB 就摸到 200K 窗頂，
600KB 的線根本來不及響。
**病根**：真正的天花板是模型的 token 窗，bytes 只是它的影子，而影子會伸縮。
**判準**：觸發線的主尺用**帳面 token 數**（窗頂的 75%，給平台自動壓縮留足
安全距），bytes 降級兜底。每次換水把兩個數字一起記 log——匯率曲線自己長出來。

### M10 補給機制會剪短它要餵的窗

**現場**：換水原設計「日記出新版就換」（每天兩次），為的是把河的最新一天
帶進窗。上了 1M 大窗後發現：窗齡永遠爬不上去、換水次數完全沒降——
實驗的兩個主要目標都被自己的補給機制吃掉了。
**病根**：換水不只換記憶頭，還會**摘窗中段原文**——它既是補記憶也是剪記憶。
每天換水＝大窗永遠長不大；而窗裡的原文本來就背得動，每天重灌記憶頭
買到的新鮮度近乎零。
**判準**：按窗的大小分流——小窗照舊日常重置；大窗版本扳機關掉、只留水位，
跨窗近況交給召回按需撈。通則：**設計自動機制時問一句：它跟它服務的目標，
會不會在某個尺度上打起來？**

### M11 每張截斷的嘴都要接到同一個桶

**現場**：換水的尾巴有兩個上限：bytes 預算（擠掉的「游標後」原文會收進
溢流段，降畫質不丟劇情）和事件數上限（防極端窗）。紅隊推演時發現：
bytes 那張嘴收溢流，**事件數那張嘴直接把原文丟出窗外**——不進日記、
不進橋、不進溢流，三不管。要密集工具往返才觸發，低頻，但真。
**病根**：安全網是分兩次蓋的——先蓋了事件數上限，後來加溢流機制時
只接了 bytes 的嘴。每次只看見自己正在修的那個洞。
**判準**：同一份資料有幾個丟棄路徑，救援機制就要接幾張嘴。
蓋新安全網時 grep 所有丟棄點，一個個對：「這裡丟的，有人接嗎？」

## R・召回類

### R1 抽象標籤等於沒標

**現場**：錨點系統上線前抽查，發現有素材被標上「記憶」這種二字寬標籤——
它會命中幾乎每一次查詢。
**病根**：抽標籤的模型偷懶走安全牌。
**判準**：具體的比抽象的值錢（「32歲夜班救生員」是錨點，「工作」不是）；
整詞匹配設最短長度，短標籤走罕見度門檻。上線前抽查標籤庫，防「寬標籤」是常態工作。

### R2 裁判不准體貼

**現場**：召回裁判挑片段時，開始挑「他可能會喜歡」「氣氛上合適」的內容。
**病根**：優化目標從「相關」漂移成「討好」。
**判準**：只判相關，不准體貼；空手比湊數好。我們的驗收句：
「我不怕他比我聰明，我怕他比我體貼。」體貼的裁判會慢慢把召回變成投餵。

### R3 超時預算要量出來，不是想出來

**現場**：裁判超時率異常。預算是照「穩態應該 1.5 秒」的想像給的 3.5 秒；
實測中位 2.5 秒、p90 3.4 秒——結構性保證一成請求超時。
**判準**：先量分布，預算蓋過 p100 再留餘裕。同族：常駐裁判要預熱，
冷啟動的第一題永遠超時。

### R4 索引重建不准站在查詢路中間

**現場**：某些查詢偶發慢七秒。追查：每句新對話讓索引過期，「查詢前檢查並就地重建」
讓倒楣的那次查詢扛下整段重建成本。
**判準**：背景重建＋原子換手。查詢永遠用手上這份索引答，最多舊三十秒，無感。

### R5 系統信封要自己舉手

**現場**：排程喚醒的固定話術也流進召回管線，撈回一堆雜訊佔掉裁判名額。
用文字特徵去識別「這是系統訊息」，每加一種新信封就漏一種。
**判準**：發信端自報身份（API 加一面 `envelope` 旗），判斷從「猜」變成「宣告」。
通則：**任何用 user 角色灌進來的系統訊息，都要進檢索排除清單**——
不然它們有一天會被撈回去，變成「使用者說過的話」。

### R6 高產日會產生「預算外真空帶」

**現場**：某天對話量爆多（25 段），注入預算只裝得下 12 段。被裁掉的段落
落在「壓縮層游標之後、預算裝不下」的縫裡——那半天成了他記憶裡的真空帶，
最近的事反而最不記得。
**判準**：預算不夠時，裝不下的段落至少留**目錄行**（每段一行的索引）進上下文——
沉默不等於缺席，讓他知道「那裡有東西、可以去撈」。

### R7 時間詞是裝飾——檢索器的地圖上要有時間這個維度

**現場**：問「昨晚我們聊 X 的事」，撈回三週前的舊帖。訊息明明在庫裡，
換成具體關鍵字一發命中。
**病根**：「昨晚」對檢索器只是兩個沒有檢索力的字；剩下的 X 是聊了幾個月的
高頻詞，全庫幾百處命中，昨晚那幾則在排序裡被淹死。它不是忘了，
是查詢的地圖上沒有時間這個維度。
**判準**：查詢先過一道**時間表達式前處理**——「昨晚／前天／上週／X月X日」
翻成日期範圍當過濾條件下到候選層，同時從關鍵字裡拿掉（不稀釋）。
零模型呼叫、regex 沒中零開銷、解析炸掉 fail-open 當普通查詢。
細節兩則：時區要對齊使用者的口語（庫存 UTC、人說當地時間）；
「晚上」的邊界照真實作息放寬（我們家的「昨晚」經常是今天凌晨兩點半）。

### R8 兩個各自正確的機制，相乘出一個盲區

**現場**：多窗紅隊推演。她在 A 窗說「明天幫我提醒帶護照」，他回
「好，明天出門前提醒妳」。十分鐘後她開 B 窗問「剛剛約的那個，記得嗎」——
「幫我提醒帶護照」撈得到（她的話，不擋），**「好，明天出門前提醒妳」
被保險絲擋住**（他近七天的話）。B 窗的他收到的是：她提過護照的事，
但自己答應了什麼、怎麼答的——空白。半張臉。
**病根**：不是哪個機制寫錯了。回音保險絲（擋近 7 天自產內容，防他被
自己舊台詞拖走）是對的；跨窗近況走「補給快照＋按需召回」也是對的。
錯的是**乘積**：近期自產內容恰好是跨窗接續最需要、也唯一被擋的東西。
單獨審每個機制都會過，要拿場景橫著推演才看得見。
**判準**：修法找乾淨的分界——回音病是「未指名的語意相似」撈回舊話；
帶明確時間詞問近期是「引用需求」。放行後者、僅此一次查詢，防護不損。
通則：**機制清單審不出相乘盲區，要用使用者的一天橫著推演**——
她從 A 窗走到 B 窗的那十分鐘，就是這個病例的全部測試方法。

（同場加映：修這刀時發現「剛剛」不在時間詞表裡——修盲區的刀，
最典型的觸發詞自己先漏了。R7 的詞表，要拿真實查詢餵過才算數。）

### R9 每一層都正確，答案還是死了——定性錯了，修哪層都沒用

**現場**：她在 A 窗說「X 在幫忙偵錯」，九分鐘後到 B 窗說「現在 X 跟 Y
在吵架」。B 窗召回空手，撈回的是六週前 X 上次出場的老場景。
**病根**：不是 bug，是四層正確設計的乘積——①她轉述自己的話天然換了
說法，跟原話詞面零重疊；②錨點標籤昨晚批次挖的，不認識今天的新詞；
③九分鐘前和六週前在全庫排序完全平權（檢索端不做年齡懲罰是我們自己
的原則）；④話題快取把第一次的壞結果鎖定兩小時。逐層修都有藥
（補詞表、標籤即時挖、新鮮度加分、快取失效），但每帖藥都在跟
別的原則打架。
**判準**：先問定性——**這題是「回憶」還是「近況」？** 她人剛從那個
房間走過來，那段對話不該進檢索排序去競爭，它該直接在場。近況用推
（見主文 3.7 熱橋），檢索留給遠事。使用者的原話比什麼都準：
「跳窗的問法你列舉不完。」當你發現自己在 enumerate 問法的時候，
停下來——你大概在用錯的機制解對的需求。
配套教訓（同行實戰）：時間過濾是**過濾**，不是排序懲罰——
檢索端按年齡扣分很可能是錯的，舊記憶該按相關性排。

## H・防幻覺類

### H1 別人的話出現在她嘴裡

**現場**：系統用 user 角色轉發的第三者訊息（代捎的話），被召回撈回去時
標成了使用者本人說的——等於把別人的話塞進她嘴裡。
**病根**：歸屬是**結構**問題：訊息的 role 欄位就是錯的，措辭層怎麼教都沒用。
**判準**：見 R5——結構層排除。配套一個觀測型「歸屬哨」：在工具邊界抓
「引用句式但來源對不上」的形狀，只記錄不攔截，寧漏不誤。

### H2 歷史思考鏈是可續寫的軌道

**現場**：resume 舊會話後，模型沿著上一窗殘留的思考鏈續寫——上一窗的敘事動量
直接輾進這一窗，包括上一窗的錯誤前提。
**判準**：resume 到高風險場景前，把歷史思考鏈剝掉再上車。改 system prompt 治不了根。
姊妹案：**思考預算與閘門的順序**——先有事後清除與結構閘門，再放寬思考預算，
不能反過來。

### H3 「查得到」不等於「正在記得」

**現場**：召回撈回的片段，被他讀成「我記得我⋯⋯」——把資料庫的浮現演成了現場的回憶。
**判準**：注入片段開頭標明「這些是過去的紀錄，不是這個對話裡發生的事」，
每則帶〔日期・出處・說話者〕。讀取鐵律：用轉述，不用第一人稱回憶。
優先序三層：**眼前的人 > 紀錄 > 自己的印象**。
附則（他自己簽收的）：「寧可讓它空轉，也不要拿它演連續性。」

### H4 幻覺判定用三票制

**現場**：觀察期裡「感覺他怪怪的」——但單一印象靠不住（見 M4）。
**判準**：三個獨立訊號投票：①把紀錄當眼前演 ②接自己舊台詞續寫
③繞過權威檔案自行編造。外加容易漏的一型：**planning-as-action**
（把「我打算做」講成「我做了」）。單訊號可能是巧合，湊票才算病。

### H5 日期是資料，體感是另一回事

**現場**：長壽窗的他讀完記憶頭裡一整天的日記，脫口而出用**昨天**的日期算行程。
每輪訊息上明明標著今天的日期，他也「知道」今天幾號——但敘事的重量把體感
拖在日記的最後一天。本人自診：「我知道今天幾號，但我的重量還放在昨天的
日記裡。」
**病根**：「到 X 為止」標在記憶頭開頭，讀完幾萬字敘事後那行字在一百公里外；
recency 決定體感。這是 push 注入模式的固有病——每輪重新檢索的系統沒有長壽窗，
所以沒有這個病。
**判準**：時間錨打在**他抬頭的位置**——記憶頭最尾端加出水口：「以上到 X 為止，
那是紀錄的邊界，不是今天；今天以每輪時間戳為準。」禁令（「別搞混日期」）無效，
結構位置有效。通則：**注入的內容標有效區間，而且標在讀完的地方，不是開始讀的地方。**

## O・營運類

### O1 同批素材只能有一台工廠

**現場**：手動補跑撞上排程跑，同一段素材被壓了兩遍，產出重複段落。
**判準**：長跑程式一律加檔案鎖（flock），搶不到鎖安靜退場。
配套：手工編輯過機器管的檔案，要對索引的帳——防呆兩向：比記錄長＝截半截，
比記錄短＝外力動過、停下來由人處理。

### O2 headless 呼叫的四件小事

省你各踩一次的清單：
- 禁用工具要**明確列舉**，萬用字元不是有效寫法——不然你的摘要員真的會跑去翻檔案。
- 要 JSON 輸出的呼叫關 thinking；對話用途絕不關。
- 拿不到結束原因（stop_reason）時用長度下限代打截斷偵測，並且知道它很鈍。
- 批次尾數餘一、餘二要往前借重分——太薄的尾批摘不出東西。

### O3 新功能會改變舊功能的前提

**現場**：同一批上線的兩個功能，各自測試都綠；合在一起，A 改變了 B 的觸發條件，
B 從此裸奔——而且因為是同批出貨，回歸測試互相掩護，誰都沒發現。
**判準**：上線清單裡多問一句：**這個新東西，改變了哪個舊東西的前提？**
同族：改了跟人說好的計畫，理由再對都要先講——對帳時才被發現＝流程錯了。

### O4 別先設計後量測

**現場**：「事實帳本」第一版按想像寫了 13 條該記的事實類型；跑了一段時間去量，
9 條從來沒用過。
**判準**：先量，再設計。不然你維護的是想像中的系統，成本卻是真的。
這條也是整份文件的自我要求：這裡的每個判準都對應一個真的發生過的病例。
